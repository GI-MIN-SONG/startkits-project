# Claude 명령어: Update Roadmap

완료된 shrimp 작업을 `ROADMAP.md`의 출시 체크리스트·의사결정 상태와 대조해 갱신 초안을 제시합니다.

## 사용법

```
/docs:update-roadmap
```

## 프로세스

1. `mcp__shrimp-task-manager__list_tasks`(status: all)로 전체 태스크를 조회하고, `completed` 상태 태스크의 name/summary/completedAt을 수집한다.
2. `ROADMAP.md`를 읽어 다음 두 구조를 파싱한다.
   - 9장 "출시 체크리스트"의 각 `- [ ]` 항목
   - 8장 의사결정 표의 각 행 중 `상태` 컬럼이 `미정`/`제안 상태`/`보류`인 행
3. shrimp 완료 태스크의 name/summary를 로드맵 체크리스트 항목·의사결정 항목과 의미적으로 매칭한다. 매칭 근거(어떤 태스크가 어떤 항목을 뒷받침하는지)를 명시한다.
4. 매칭됐지만 아직 미완료로 표시된 항목을 "체크 후보" 목록으로 정리한다. 이 단계에서는 **파일을 수정하지 않는다.**
5. 근거가 간접적이거나 완전히 일치하지 않는 항목은 "판단 보류" 목록으로 분리하고 이유를 남긴다.
6. 사용자에게 체크 후보 목록을 보여주고 반영 여부를 확인받는다.
7. 승인된 항목만 `Edit`으로 반영한다.
   - 9장: 해당 `- [ ]`를 `- [x]`로 변경
   - 8장: 해당 행의 `상태` 컬럼을 `확정`으로 변경하고, `### 확정 기록` 아래에 `- **D-XX (항목명)**: <근거 요약>. <오늘 날짜> shrimp 태스크 완료 기준 반영.` 불릿을 추가
8. 반영 후 `git diff -- ROADMAP.md`로 변경된 라인만 사용자에게 보여준다.

## 결과 리포트 포맷

사용자 확인을 요청할 때는 아래와 같은 형태로 후보를 제시한다.

```
### 체크 후보 (승인 시 반영)
- [ ] → [x] 9장: "실제 Notion 견적서와 공개 토큰으로 end-to-end 조회에 성공했다."
  근거: <shrimp 태스크명> 완료 (<completedAt>) — <summary 요약>
- D-XX 상태: 미정 → 확정
  근거: <shrimp 태스크명> 완료 — <summary 요약>

### 판단 보류 (근거 불충분)
- 9장: "..." — 관련 완료 태스크를 찾지 못함
```

전체 후보가 없으면 "현재 완료된 shrimp 작업으로 새로 체크할 항목이 없습니다"로 보고를 마무리한다.

## 참고사항

- shrimp 태스크 조회가 실패하거나 완료 태스크가 없으면 중단하고 원인만 보고한다. git log 등으로 임의 추론해 대체하지 않는다(완료 판단 기준은 shrimp-task-manager 태스크 상태로 고정).
- 사용자 승인 없이 체크박스나 의사결정 상태를 확정으로 바꾸지 않는다.
- 8장의 "미정"/"제안 상태" 항목을 임의로 "확정"시키는 것은 `shrimp-rules.md`의 AI 의사결정 기준 위반이므로, 근거가 된 shrimp 태스크 summary를 반드시 함께 제시한다.
- 로드맵 구조 자체를 새로 설계하거나 단계를 개편하는 작업은 이 커맨드의 범위가 아니다. 필요하면 `roadmap` 서브에이전트 사용을 안내한다.
