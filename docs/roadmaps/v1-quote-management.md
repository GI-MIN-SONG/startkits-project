# 견적서 관리 기능 로드맵 (v1)

> 프로젝트: Invoice Web — Notion 견적서 공유 서비스
> 문서 성격: 신규 기능 로드맵 v1 (`ROADMAP.md` 단계 1~3 이후 첫 번째 기능 단위)
> 기준 문서: `docs/PRD.md`, `ROADMAP.md`, `shrimp-rules.md`
> 기준일: 2026-08-23
> 기술 기준: Next.js 16 App Router, React 19, TypeScript, Tailwind CSS v4, shadcn/ui(`base-nova`), Vitest, Playwright MCP

**이 문서는 `ROADMAP.md`의 단계 1~3 완료(단계 3은 토큰 시스템 보류로 부분 완료)를 전제로 한 신규 기능 로드맵(v1)이며, `ROADMAP.md` 본문은 수정하지 않는다.** 여기서 새로 정의하는 의사결정 항목은 `ROADMAP.md` 8장의 D-01~D-17과 번호가 겹치지 않도록 이 문서 전용 체계인 `D-V1-xx`를 사용한다.

## 1. 목적과 배경

`ROADMAP.md` 단계 3에서 "링크 하나를 열면 견적서가 보인다"는 클라이언트 쪽 흐름은 완성됐다. 그러나 발행자(관리자) 쪽에는 화면이 없다. 발행자는 지금 Notion에서 페이지 ID를 직접 복사해 `/quote/<ID>` 형태로 URL을 손으로 조립해야 하며, 어떤 견적서가 승인 상태인지도 Notion을 열어야만 알 수 있다.

이 로드맵의 목표는 그 병목만 제거하는 것이다. 발행자가 관리자 화면에서 견적서 목록을 확인하고, 버튼 하나로 공유 링크를 클립보드에 복사할 수 있게 한다.

### 이 단계가 지금 가능한 이유

- 목록 조회는 이미 확정된 데이터 계약(`QuoteResult`, `parsers.ts`, `errors.ts`)과 재시도 로직(`retry.ts`)을 그대로 재사용한다.
- 공개 토큰(`D-08`/`D-09`) 결정에 의존하지 않는다. 복사되는 링크는 현재 URL 구조 그대로다.
- 따라서 단계 3이 "부분 완료" 상태여도 착수할 수 있다.

## 2. 현재 구현 기준선 (이 단계 착수 시점)

### 재사용할 수 있는 것

- `src/lib/quotes/errors.ts` — `QuoteErrorKind` 5종과 `QuoteResult<T>`. 목록 조회도 같은 분류를 쓴다.
- `src/lib/quotes/parsers.ts` — `parseTitle`/`parseRichText`/`parseDate`/`parseNumber`/`parseStatusOption`.
- `src/lib/quotes/retry.ts` — `fetchWithRetry()`. `Retry-After` 존중, 총 대기 상한 5초.
- `src/lib/quotes/logger.ts` — allowlist 기반 구조화 로그.
- `src/lib/quotes/__fixtures__/` + `__tests__/notion.contract.test.ts` — fixture + `vi.stubGlobal("fetch", ...)` 계약 테스트 패턴.
- 전역 다크모드(`next-themes`, `.dark`, `globals.css`의 oklch 토큰), `ThemeToggle`, Sonner `Toaster`.

### 이 단계에서 처음 손대는 것 (주의 필요)

- **`NOTION_DATABASE_ID` 환경변수는 `.env.example`에 선언만 되어 있고 실제 코드에서 쓰이지 않는다.** `notion.ts`는 `ITEMS_DATABASE_ID`만 하드코딩 상수로 갖고 있다. 목록 조회가 이 환경변수의 첫 사용처가 되므로, 미설정·오타 상황의 동작을 새로 정의해야 한다.
- 지금까지 Notion 조회는 항상 "단건 페이지 + 그에 연결된 items"였다. DB 전체를 목록으로 질의하는 경로는 없었다.
- `src/app/admin/*`, 관리자 레이아웃은 존재하지 않는다.

## 3. 범위 (2026-08-23 사용자 확정)

이 단계는 아래 3가지로 범위를 고정한다. 목록에 없는 항목은 구현하지 않는다.

### 포함

1. 관리자 레이아웃에서의 견적서 **목록 조회**
2. 목록에서의 **공유 링크 복사**
3. 신규 화면의 **다크모드 정합성 점검·보정**

### 제외 (명시적)

- 견적서 **생성·수정·삭제**. Notion 쓰기 API를 호출하지 않는다.
- **공개 토큰 발급/폐기/회전 시스템.** `ROADMAP.md`의 D-08/D-09는 이번에도 보류를 유지한다. 복사되는 링크는 현재 구조 그대로 `/quote/<Notion 페이지 ID>`다. 즉 이 단계는 "링크를 손으로 조립하지 않아도 되게" 만들 뿐, 링크의 형태나 접근 제어 방식을 바꾸지 않는다.
- **관리자 인증·로그인 구현.** 요구사항에 명시되지 않았으므로 임의 설계하지 않고 `D-V1-01`(미정)로 남긴다.
- **새 다크모드 시스템.** 기존 전역 테마 체계를 점검·보정할 뿐이다.

### 우선순위

| 요구사항 | 우선순위 | 근거                                          |
| -------- | -------- | --------------------------------------------- |
| 4-1 목록 | P1       | 발행자 워크플로 병목 해소                     |
| 4-2 복사 | P1       | 목록 없이는 의미가 없어 4-1과 함께 완료       |
| 4-3 다크 | P1       | 신규 화면 품질 기준, 4-1/4-2 구현과 동시 진행 |

## 4. 요구사항 4-1 — 관리자 레이아웃 견적서 목록

**목표:** `/admin/quotes`에서 Notion `invoices` DB의 견적서를 목록으로 조회한다.

**선행 조건:** `NOTION_API_KEY`와 `NOTION_DATABASE_ID`가 로컬 `.env`에 설정되어 있고, integration이 `invoices` DB에 연결되어 있다.

### 구현 작업

- 관리자 레이아웃(`src/app/admin/layout.tsx`)과 목록 라우트(`src/app/admin/quotes/page.tsx`)를 추가한다. `loading.tsx`/`error.tsx`를 상세 페이지와 동일한 App Router 파일 컨벤션 세트로 함께 둔다(`shrimp-rules.md`: 상태 처리를 페이지 내부 분기로 대체하지 않는다).
- Notion `databases/{NOTION_DATABASE_ID}/query`를 호출하는 서버 전용 함수(예: `fetchNotionQuoteList`)를 `src/lib/quotes/notion.ts`에 추가한다. 파일 최상단의 `import "server-only"`는 그대로 유지된다.
- `src/lib/quotes/index.ts`에 `getQuoteListResult()`로만 노출한다. 페이지에서 `notion.ts`를 직접 import하지 않는다(단일 진입점 규칙).
- `NOTION_DATABASE_ID`를 실제로 읽어 쓴다. 미설정 시 크래시가 아니라 명확한 실패 경로로 처리하고, 오류 메시지에 환경변수 **값**을 넣지 않는다.
- 목록 행 타입 `QuoteListItem`(`id`, `title`, `client`, `issueDate`, `status`)을 `types.ts`에 추가한다.
  - **상세용 `Quote`를 재사용하지 않는다.** 목록에서는 라인 아이템을 조회하지 않으므로 `items: []`가 되고, 그러면 `quoteTotal()`이 0을 반환해 "합계 0원"이라는 금액 오표시로 이어진다. 금액 오표시는 `ROADMAP.md` 7장에서 "매우 높음" 영향으로 분류된 리스크다.
- **목록에는 `상태`='승인' 게이트를 적용하지 않는다.** 발행자는 대기·거절 건도 봐야 한다. 상태는 배지로 그대로 표시한다.
  - **단, 상세 페이지(`fetchNotionQuote`)의 `isPublishable` 게이트는 절대 건드리지 않는다.** 목록의 노출 정책과 상세의 공개 정책은 별개다.
- `has_more`/`next_cursor` 페이지네이션을 처리한다. 수집 범위는 `D-V1-03`을 따른다(결정 전에는 첫 페이지만 조회하고 "더 있음"을 화면에 표기).
- 정렬·필터는 `D-V1-02`를 따른다(결정 전에는 Notion 기본 순서를 쓰고 화면에 정렬 기준을 표기하지 않는다 — 근거 없는 정렬 표기가 사용자를 오도하는 것을 막기 위함).
- 반환 타입은 `QuoteResult<QuoteListItem[]>`. **새 오류 종류를 추가하지 않는다.** 기존 5종으로 충분하다.
- `logger.ts`의 `ALLOWED_FIELD_KEYS`에 목록용 필드(예: `rowCount`)가 필요하면 의도적으로 추가한다. 클라이언트명·견적서 번호 등 고객 데이터는 추가하지 않는다.
- 헤더 노출: `D-V1-01`이 미정인 동안 `header.tsx`의 `navLinks`에 관리자 링크를 **추가하지 않는다**(URL 직접 접근만). 추후 노출하기로 하면 `navLinks`가 데스크톱·`MobileNav` 공통 단일 소스이므로 그 배열만 수정한다.

### 완료 조건(DoD)

- `/admin/quotes`가 견적서 번호, 상태, 클라이언트명, 발행일 4개 열로 목록을 표시한다.
- 목록 0건이면 빈 상태 UI, 실패면 오류 상태 UI가 나오고 흰 화면·미처리 예외가 없다.
- `NOTION_API_KEY`/`NOTION_DATABASE_ID`가 HTML, 클라이언트 번들, 콘솔 로그 어디에도 없다.
- 아래 Vitest 계약 테스트가 전부 통과하고, Playwright MCP 검증이 완료된다.

## 5. 요구사항 4-2 — 공유 링크 복사

**목표:** 목록에서 버튼 한 번으로 `/quote/<id>` 절대 URL을 클립보드에 복사한다.

**선행 조건:** 4-1의 목록이 렌더되고 각 행이 `quoteId`를 갖고 있다.

### 구현 작업

- `src/components/quote/copy-link-button.tsx`를 **클라이언트 컴포넌트**(`"use client"`)로 만든다. 클립보드는 브라우저 API이므로 서버 컴포넌트일 수 없다.
- 서버 컴포넌트인 목록 페이지에서 `quoteId`만 prop으로 넘긴다.
- **이 컴포넌트는 `@/lib/quotes`(index.ts)를 import하지 않는다.** `shrimp-rules.md`에 기록된 `error.tsx` 예외와 같은 이유로, index를 거치면 `notion.ts`/`logger.ts`/`retry.ts` 등 `server-only` 모듈이 클라이언트 번들 경로에 딸려 들어가 빌드가 깨진다. 필요한 순수 코드만 개별 파일에서 직접 import한다.
- 복사 대상은 `${origin}/quote/${quoteId}`. origin은 `window.location.origin`을 사용한다(배포 환경별 하드코딩 금지).
- URL 조립은 컴포넌트에 인라인하지 말고 순수 함수 `buildQuoteShareUrl(origin, quoteId)`로 분리해 단위 테스트 대상으로 만든다.
- 성공·실패 피드백은 이미 전역 설치된 Sonner(`Toaster`)를 재사용한다. 새 토스트 라이브러리를 도입하지 않는다.
- `navigator.clipboard`를 쓸 수 없는 환경(비 HTTPS, 권한 거부, 구형 브라우저)에서는 실패 토스트와 함께 URL을 선택 가능한 텍스트로 노출하는 대체 경로를 제공한다.
- 버튼은 `aria-label`로 어떤 견적서의 링크인지 구분되게 하고, 키보드 포커스와 Enter/Space 조작을 지원한다.
- 아이콘이 필요하면 `lucide-react`만 사용한다.

### 완료 조건(DoD)

- 클릭 시 정확한 절대 URL이 클립보드에 들어가고, 붙여넣은 링크로 `/quote/[id]` 상세가 정상 조회된다.
- 클립보드 실패 시에도 콘솔에 미처리 예외가 없고 사용자에게 실패가 안내된다.
- `buildQuoteShareUrl`에 단위 테스트가 있고 전부 통과한다.

| 정상 | localhost origin(포트 포함)         | 포트가 유지됨                                  |
| 경계 | origin 끝 슬래시 있음 / 없음        | 슬래시가 중복되지 않음                         |
| 경계 | 하이픈 포함 / 미포함 32자 Notion ID | 원본 그대로 유지, 임의 변형 없음               |
| 경계 | 빈 문자열 · 공백만 있는 ID          | 링크를 만들지 않고 명시적으로 실패             |
| 보안 | ID에 `../`, `?`, `#` 포함           | 인코딩되어 경로 이탈·쿼리 주입이 발생하지 않음 |

### 테스트 시나리오 — Playwright MCP

1. `/admin/quotes`에서 첫 행의 "링크 복사" 클릭 → 성공 토스트 확인.
2. 클립보드 값을 읽어 기대 URL과 일치 확인(권한 부여 필요). **클립보드 읽기가 차단되면 통과로 표기하지 않고 미검증으로 기록한다.**
3. 복사한 URL로 이동 → 승인 건은 상세가 정상 렌더. 대기/거절 건 링크는 404 경험으로 수렴하는지 확인.
4. Tab → Enter 키보드만으로 복사 동작 확인.
5. 콘솔 오류 0건 확인.

### 예상 실패 조건과 대응

- 로컬 HTTP 환경에서 `navigator.clipboard`가 `undefined` → 대체 경로가 동작하는지 확인하고, 이 상태를 실패가 아닌 **정상 분기**로 테스트한다.
- 대기/거절 견적서 링크를 복사해 공유하면 클라이언트가 404를 본다 → 경고 표기 여부는 `D-V1-04`로 남긴다.

## 6. 요구사항 4-3 — 신규 화면 다크모드 정합성

**목표:** 새로 만드는 관리자 화면이 기존 전역 다크모드와 어긋나지 않게 한다. **새 다크모드 시스템을 만들지 않는다.**

**선행 조건:** 4-1 목록 화면이 렌더된다.

### 구현 작업

- 기존 `next-themes` + `.dark` 클래스 + `globals.css`의 oklch 토큰 체계를 그대로 사용하는지 점검하고, 어긋난 부분만 보정한다.
- 신규 파일에서 하드코딩 색상(`text-white`, `bg-gray-100`, 임의 hex 등)을 쓰지 않고 `bg-background`/`text-foreground`/`border-border`/`text-muted-foreground` 등 토큰 클래스만 사용한다.
- 상태 배지(승인/대기/거절)가 라이트·다크 양쪽에서 명도 대비를 확보하게 한다. 새 색이 필요하면 임의 값이 아니라 `globals.css`의 토큰으로 정의한다.
- 관리자 화면에서도 `ThemeToggle`에 접근할 수 있는지 확인한다(전역 헤더를 쓰면 자동, 별도 셸을 만들면 명시적으로 배치).
- SSR/CSR 테마 mismatch 경고가 새로 발생하지 않는지 확인한다(`suppressHydrationWarning`은 루트 레이아웃에 이미 있다).

### 완료 조건(DoD)

- 라이트/다크/시스템 3가지 테마에서 목록의 텍스트·배경·테두리·배지가 모두 판독 가능하다.
- 테마 전환 시 깜빡임이나 hydration 경고가 콘솔에 없다.
- 신규 파일에 하드코딩 색상 클래스가 남아 있지 않다.

### 테스트 시나리오

- **정적 점검:** 신규 파일에서 토큰 외 색상 클래스 사용 여부를 grep으로 확인.
- **Playwright MCP:** 라이트 → 다크 → 시스템 순으로 전환하며 각 상태의 스냅샷·스크린샷 확보, 콘솔 경고 0건 확인. 320px과 1440px에서 각각 반복.
- **Playwright MCP:** 다크모드에서 상태 배지 3종(승인/대기/거절)이 모두 배경과 구분되는지 확인.

## 7. 필수 검증 절차

모든 구현 작업에 아래 순서를 적용한다. 구현 단계는 해당 테스트가 **실제로 실행되어 통과한 뒤에만** 완료로 간주한다.

1. 변경 범위에 맞는 단위·계약 테스트를 작성하거나 갱신한다.
2. 관련 테스트를 실행하고 결과를 확인한다.
3. 앱을 실행한 뒤 Playwright MCP로 실제 브라우저에서 사용자 흐름을 검증한다.
4. 브라우저 콘솔 오류, 실패한 네트워크 요청, 로딩·성공·빈 상태·오류 상태를 확인한다.
5. lint, 타입 검사, 빌드, 포맷 검사, 회귀 테스트를 수행한다.
6. 실패 항목을 수정한 뒤 실패했던 테스트와 관련 회귀 테스트를 다시 실행한다.

Playwright CLI나 임의의 브라우저 자동화를 Playwright MCP 검증의 대체물로 취급하지 않는다. Playwright MCP나 필요한 테스트 환경을 쓸 수 없으면 생략하거나 성공으로 표시하지 말고, 미검증 항목과 필요한 설정을 차단 사유로 기록한다.

### 최종 검증 명령

#### D-V1-01 — 관리자 화면 접근 제어 (미정)

이번 요구사항에 관리자 인증이 명시되지 않았으므로 **기본 제안조차 두지 않는다.** 결정 전까지 `/admin/*`을 운영 환경에 공개 배포하지 않는다.

| 옵션                                                    | 장점                                       | 단점                                                                                                                                       |
| ------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| A. 인증 없음 (현 상태 연장)                             | 구현 비용 0, 로컬·개인 사용에 충분         | URL을 아는 누구나 전체 클라이언트명·발행일 목록을 열람. 상세 페이지가 1건만 노출하는 것과 달리 **노출 범위가 전체 고객 목록으로 넓어진다** |
| B. 환경변수 기반 단일 비밀번호 게이트 (미들웨어 + 쿠키) | 구현 비용 낮고, URL 유출만으로는 열람 불가 | 비밀번호 공유·회전이 수동, 사용자 구분 불가, 감사 로그 없음                                                                                |
| C. 외부 인증 연동 (Vercel 배포 보호, OAuth 등)          | 사용자 구분·회수·감사 가능                 | MVP 범위 대비 과할 수 있고 배포 환경에 의존                                                                                                |

**참고:** 어떤 옵션이든 `ROADMAP.md`의 D-08/D-09와는 별개 문제다. D-V1-01은 "목록을 누가 보는가", D-08/D-09는 "공유 링크가 추측 가능한가"를 다룬다. 이 단계에서 D-08/D-09의 보류 상태를 바꾸지 않는다.

#### D-V1-02 — 목록 정렬·필터 기준 (제안 상태)

제안: `발행일` 내림차순(최신 우선). 상태 필터는 이번 범위 제외.

트레이드오프: Notion `sorts` 파라미터로 서버 정렬하면 페이지네이션과 일관되지만, 정렬 키 프로퍼티가 비어 있는 행의 위치가 불확실하다. 클라이언트 정렬은 구현이 쉽지만 부분 수집(D-V1-03)과 결합하면 "가져온 것 중에서만 정렬"이 되어 사용자를 오도한다. **D-V1-03과 함께 결정해야 한다.**

#### D-V1-03 — 목록 페이지네이션 방식 (제안 상태)

제안: Notion 기본 `page_size`(100) 기준 전량 수집, 100건 초과 시 재검토.

트레이드오프: 전량 수집은 화면 로직이 단순하고 정렬이 정확하지만, 건수가 늘면 응답 시간과 Notion 호출량이 선형 증가하고 `retry.ts`의 5초 대기 상한과 맞물려 렌더가 지연될 수 있다. 부분 수집(예: 25건 + 더 보기)은 초기 응답이 빠르지만 커서 상태 관리와 정렬 정확성 문제가 따라온다.

#### D-V1-04 — 미승인 건 링크 복사 (제안 상태)

제안: 대기·거절 건도 복사는 허용하되 "클라이언트에게는 404로 보임" 경고를 표기.

트레이드오프: 복사를 아예 막으면 실수는 확실히 예방되지만, 발행자가 승인 전에 링크를 미리 준비하는 흐름을 막는다. 경고만 두면 유연하지만 발행자가 경고를 무시할 수 있다.
